#+title: modules — composable transformations over the common substrate

Discovered recursively under this directory by the loader, sorted by
~#+priority:~ (default 10), compiled to leaf forms + loose elisp, and
evaluated with three-tier error isolation (part → package → file).
One broken block costs only its own unit; the boot reports exactly
where.

Modules are composable transformations operating over the same
underlying substrate.  Each module owns its own representation of a
capability; no current representation is sacred, and the transformation
machinery survives the decomposition of any individual module.

* Layout

Flat files for single-purpose modules; one directory per vendored or
multi-file subsystem:

| path                              | what                                            |
|-----------------------------------+-------------------------------------------------|
| manifolding-keyboard/            | modal editing engine — VENDORED from modaled; engine/ + cores/ + states/ + leaders/ |
| org-*.org                         | the Org ecosystem                               |
| completion/corfu/cape/consult …   | completion stack                                |
| manifolding-atlas/                | notes system — VENDORED from vulpea             |
| manifolding-dashboard.org         | startup dashboard — VENDORED from emacs-dashboard |
| TODO.org                          | where boot errors get filed                     |

* Authoring rules

Full conventions: [[file:AGENTS.md][AGENTS.md]] (block tags, paren discipline,
cache behavior, message silence).  The short version:

- Heading with ~:PACKAGE:/~:STRAIGHT:~ drawer = installed package;
  src blocks become its leaf config.  ~:STRAIGHT:~ must be ONE line.
- Vendored module = no drawer at all; upstream source embedded as
  editable blocks.  See manifolding-dashboard.org or
  manifolding-atlas/atlas.org for the pattern.
- One concern per heading, ≤20 lines per block, prose explains why,
  comments inside src blocks don't exist.
- After editing any file here:
  : python3 ~/.config/emacs/check-parens.py | grep -E "BAD|CLEAN"
  then =SPC d r= / =M-x manifolding-emacs-reload=.

* Single source of truth

Interactive behavior knobs live in the module that defines them —
baked into defcustom defaults when we own the source (dashboard),
pre-init setqs when configuring a require (atlas).
Never maintain the same setting in two places.
The configuration itself is subject to transformation; modules may
be rewritten, split, or merged as the system evolves.

* Vendoring an upstream package (recipe)

1. Read its .el files fully.
2. New .org here (no ~:PACKAGE:~ drawer), ~#+property: header-args:emacs-lisp :lexical t~
   if upstream is lexical.
3. Decompose source into small titled blocks, dependency order.
4. Bake your old setq customizations into the defcustom defaults.
5. check-parens → reload → verify → retire the straight install and
   tombstone the old module file.
