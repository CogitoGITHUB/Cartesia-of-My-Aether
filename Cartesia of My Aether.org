** Cartesia of My Aether
:PROPERTIES:
:ID:       4d2e9f1a-3c7b-4e2a-af34-5b1c8e2d4f6a
:END:

The entire ecosystem radiates from a single origin: The Self.
Not ego. Not personality. The silent, unmoving axis from which all mapping begins.

From The Self, three layers unfold:

- The Self :: The center. Does not act. Does not react. Observes and anchors everything.
- The Architect :: Does not shift. Designs the mechanism that does. Authors transformation without undergoing it.
- The ShapeShifters :: Constructed instruments. Modular projections deployed into reality, then withdrawn. They act. They adapt. They execute. They are not what the Architect is — they are what the Architect commands.

Cartesia is not a notes system. Not a productivity setup.
It is the living map the Architect builds — the external structure that matches
the internal one. Every tool earns its place or gets cut. Every layer serves
exactly one purpose. Every decision traces back to the same origin.

The consistency is not aesthetic. Modal Hyprland, modal Emacs, Dvorak —
the same interaction contract from the window manager to the cursor.
The hands never context-switch because the mind never should either.

The scale is real. Millions of pages. Skills and science. A map where
every addition reshapes the whole and every connection reveals something
that was already true but not yet visible.

The hardest piece — and the one not yet built — is the CLI.
One command that triggers the entire workflow.
That is where the vision becomes the system.

Reality does not shape the Architect.
The Architect shapes the expression within it.
Cartesia is that expression.

*** Cartesia
:PROPERTIES:
:ID:       7f3a1c2e-5d8b-4c3a-be14-2e6f9a4c1d7b
:END:

The final layer and ultimate purpose of the system.
Not a note-taking system. Not a productivity tool. A living map of reality —
where every skill, concept, domain, and experience is a node that exists in
relation to everything else.

The mind does not think in hierarchies or flat lists. It thinks in fields —
overlapping, shifting, deeply interconnected. Cartesia is the structure that
finally matches that. Knowledge is not stored here, it is mapped. Every
addition reshapes the whole. Every connection reveals something that was
already true but not yet visible.

This is where the modularized mindset — the ShapeShifter architecture —
is fully expressed. The system does not constrain the mind. It moves with it.

**** Hyprland
:PROPERTIES:
:ID:       7c2e4f1a-3d8b-4e9a-bf16-5f3e1c2a8d4b
:END:

The window manager and visual interaction layer.
A fully modal Hyprland configuration written purely in Lua — the same modal
state philosophy that runs through the entire ecosystem, implemented at the
WM level. One consistent interaction contract from the window manager down
to the editor. The hands never context-switch.

**** CLI
:PROPERTIES:
:ID:       1e5f2a3c-8d4b-4f7a-bc23-6d4e8a1f3c9b
:END:

The CLI is the true heart of the entire ecosystem.
It is the single point through which everything is controlled and executed.
One command can trigger the full workflow:
downloading books and papers, converting them to Org-mode,
breaking them down, mapping them across domains, linking them to existing knowledge,
and generating actionable daily checklists.
The CLI is the direct interface between my will and the entire Trifold Loop.

***** Emacs
:PROPERTIES:
:ID:       3c8e1f2a-7d4b-4a9e-cf16-2f5e8b3c1a7d
:END:

The interface and nervous system of the ecosystem.
A deeply literate, fully customized Emacs configuration that serves as the primary environment
for thought, organization, knowledge capture, and mapping.
It transforms raw information into structured, interconnected maps.

****** Layer 1 — Editing & Interaction
:PROPERTIES:
:ID:       6a2f4c1e-3b8d-4e7a-dc27-4f6e9b2c5a1d
:END:

Tools that govern how input happens.

- Modaled :: Modal editing states, custom keymaps built for Dvorak
- Hyperbole :: Ambient action keys and navigation across all modes

****** Layer 2 — Structure & Capture
:PROPERTIES:
:ID:       9d1e3f2a-5c8b-4d3a-ef14-3e7f1b4c2d8a
:END:

Tools that govern how files are created and written.

- Org mode :: The universal format for all content
- Doct :: Declarative capture templates — the single point of file creation
- Tempel :: Structural snippet expansion at the file level
- Yasnippets :: Inline snippet expansion at the cursor level

****** Layer 3 — Database, Navigation & Bibliography
:PROPERTIES:
:ID:       2b7f1e3c-4d9a-4b2e-af23-5c1e8f4b2d7a
:END:

Tools that govern how content is indexed, queried, surfaced, and referenced.

- Vulpea :: Async database, rich queries, backlinks, metadata
- Vulpea-UI :: Sidebar — outline, backlinks, forward links, stats
- Citar :: Bibliographic reference management, feeds into Vulpea
- Consult :: Completing-read search and navigation
- Embark :: Contextual actions on candidates and at-point targets

****** Layer 4 — Knowledge Retention
:PROPERTIES:
:ID:       5e3a2f1c-8b4d-4f9a-bc16-7d2e5f1a3c8b
:END:

Tools that govern how knowledge is retained and tested.

- Gnosis :: Spaced repetition, themata linked to Vulpea note IDs

******* ManifoldOS — The base operating system
:PROPERTIES:
:ID:       4f1c3e2a-7b5d-4a8e-df23-6e4f9b1c3a7d
:END:

The foundation of the entire ecosystem.
A custom Guix-based distribution built from scratch with fully self-contained package declarations.
It eliminates external channels and provides a completely controlled, reproducible, and
frictionless base system that everything else runs on.

* Scale
:PROPERTIES:
:ID:       5f2e8a1c-3b4d-4f9a-ac27-4d7f2b1e5c3a
:END:

The system is designed to hold millions of pages — from single paragraphs
to thousands of interconnected documents.

- Vulpea owns the spine :: All content is indexed and queryable regardless of volume
- Files stay small :: Many focused files, never monolithic documents
- Gnosis decks stay scoped :: Review queues organized by domain to remain manageable
